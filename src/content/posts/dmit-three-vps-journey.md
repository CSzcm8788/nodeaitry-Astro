买 DMIT 的时候，我只想给自己弄一条能长期用的线路。Mac 要工作，iPhone 和 Android 也都要用，最好像之前用机场一样，导入配置，打开开关，就不用再管了。

一个多月后，我手里多了两台香港 VPS。

这一个多月里，我问得最多的两个问题，大概就是“为什么又连不上了”和“这样是不是把事情搞复杂了”。换 IP、加中转、查分流、查 DNS，这几样都试过。现在总算可以先停下来用一阵。

先说一下我的情况：家里是湖南联通宽带，平时主要用来查资料、访问海外网站和使用 AI 服务。我并不懂多少网络知识，部署和排查大部分由 Codex 协助完成，我一边用，一边追问那些自己没弄明白的地方。这篇就记一下实际经历，不写成安装教程。

## 从直连到香港中转

最早买的是 DMIT 的洛杉矶 LAX.AS3.Pro.TINY，1 核、2 GB 内存。对我这种几台设备自己用的需求，当时并没太担心机器性能。

真正把我卡住的是 IP。

有一次，三台设备都连不上海外网站。我先怀疑客户端和分流规则，iPhone 还专门切到蜂窝网络试了，依然不行。后来排查才发现，服务器本身还在运行，从香港和美国也能连，问题出在大陆到这台服务器这一段。DMIT 客服也确认，原来的 IP 在大陆被封锁。

于是申请换 IP。10 月初拿到新地址，测了一下能连，本以为这事就结束了。没撑多久，又遇到同样的问题。

这也是我踩的第一个坑：买了一台自己的服务器，并不等于有了一条能一直从家里连过去的线路。

套餐付了两期，我自己估算累计流量还不到 50 GB，却一直在处理连不上的问题。钱付了，流量没用掉多少，排障时间倒是花了不少。

我没再干等换 IP，买了 LisaHost 的香港 HK-3CMI-H 放在前面做中转。后来又加了一台 LOCVPS 香港，当备用。

现在访问海外网站，常用的路径变成了：

**设备 → 香港 VPS → DMIT 美国 → 网站**

同时保留另一种走法：

**设备 → 香港 VPS → 网站**

第二种就是香港直出，不经过美国。国内网站则继续本地直连，没必要也跟着绕一圈。

只要香港能连上 DMIT，我就还能走美国出口。这解决了我当时最急的问题。但它没有把 DMIT 的 IP“修好”：香港入口本身也是公网 IP，一样会出问题。

## 配置导入了，不等于用上了

手机上的问题更琐碎：配置导进去了，实际跑的却可能不是它。

之前有一阵，手机上很多网站和服务打不开。我来回检查节点，后来切回其他服务商的规则文件，访问就恢复了。至少那次，不能只盯着服务器排查。

我一开始还被不同设备的配置弄晕过。明明都是我自己用，为什么要分成好几套？后来才分清楚：Mac 上的 Clash Verge 和 Android 上的 Clash Meta 可以共用一份 Clash 配置，iPhone 的 Shadowrocket 则需要另一种格式。节点信息和分流思路可以沿用，具体配置写法需要分别适配。

现在两种文件都叫 DMIT.conf，分别放在 Clash 和 Shadowrocket 的文件夹里。名字统一了，找起来省事，也不至于拿错格式。

更具体的一次就发生在最后检查 DNS 的时候：iPhone 里已经有 DMIT.conf，但实际勾选的仍然是 default.conf。更新了半天，启用的根本不是那份文件。直到重新导入、选中，再重连，新的设置才真正用上。

中间还遇到过原来的机场订阅不见了，后来我自己重新导入过。具体是哪次操作或同步造成的，没有查清楚。这之后我每次都要强调一句：只改自己的 VPS，别动其他机场。现在更新前会留备份，更新后也会核对其他配置有没有变化。

## 三台 VPS 的分工

三台机器现在的分工是这样的：

| 机器 | 现在的用途 |
| - | - |
| DMIT 洛杉矶 | 提供美国出口，保留 IPv4、IPv6 直连节点 |
| LisaHost 香港 HK-3CMI-H | 常用香港入口，可香港直出，也可中转到 DMIT；套餐带宽 30 Mbps |
| LOCVPS 香港 | 备用香港入口，同样提供直出和 DMIT 中转；套餐带宽 100 Mbps |

香港入口现在用 Hysteria2，DMIT 保留 VLESS + REALITY。我也纠结过哪个协议才是“最优解”。现在先用这套，至少连接方式、实际速度和出了问题该查哪里，已经比刚开始清楚。

Mac 日常还是选 HK-DMIT，也就是从 Lisa 香港转到 DMIT，Clash Verge 开规则模式和 TUN。Android 用 Clash Meta；iPhone 用 Shadowrocket，目前选的是 LOC-HK-DMIT，全局路由设为“配置”。

配置里留了七个节点，两家的香港直出和中转都在，DMIT 的 IPv4、IPv6 线路也留着。看着不少，平时其实不用挨个折腾。DMIT 的 IPv4 大陆直连还没恢复，IPv6 直连也要看当前网络有没有原生 IPv6。列表里有七个，能同时用的未必有七条。

## 实际速度和带宽参数

10 月 27 日在家里的联通 Wi-Fi 下，用 Android 跑了一轮对比。调完参数后测的几轮，大致是：

| 线路 | 下载 | 上传 |
| - | -: | -: |
| Lisa 香港直出 | 17.5–19.9 Mbps | 10.7–17.9 Mbps |
| Lisa 香港 → DMIT | 13.5–15.2 Mbps | 4.8–9.1 Mbps |
| LOC 香港直出 | 51.3–78.2 Mbps | 49.5–74.6 Mbps |
| LOC 香港 → DMIT | 21.7–28.7 Mbps | 24.7–25.8 Mbps |

这些是当天几次测试的范围，不能当成每天都能跑到的速度。Mac 后来单独重载 HK-DMIT 配置，下载测到约 12.7–15.1 Mbps，和上面差不多。

这里的单位是 Mbps。Lisa 标的 30 Mbps，换成下载软件常见的 MB/s，理论上限大约是 3.75 MB/s，还没扣掉开销。看到“30M”时，这两个单位得先分清。

最后 Lisa 的上下行参数设成 30/30 Mbps，LOC 直出 100/100 Mbps，LOC 到 DMIT 的中转用自动带宽。没有哪里都填最大值：实测下来，填得更大不一定更好。下载跑满的时候，网页响应反而可能变慢。

## 收拾配置，检查安全和 DNS

另外还有几件之前漏掉的事。服务器改用 SSH 密钥管理，DMIT 和 LOC 的管理端口限制了来源，不用的旧入口也关掉了。文件和备份都归到一个 VPS 文件夹，免得下次又在桌面、下载目录里翻。

DNS 也在三端重查了一遍。海外域名通过代理查询加密 DNS，国内域名走国内加密 DNS，国内网站仍然直连。Mac、Android 和 iPhone 都实际跑了 BrowserLeaks：这次检测没有出现大陆运营商 DNS，结果里看到的是 Cloudflare 和 Google。这个结果只代表当时浏览器测试中的解析路径，不代表所有应用和分流规则都已逐一验证。以后换网络或改配置，还是得重新检查。

WARP、Cloudflare 套壳，还有各种管理面板，我也都问过。最后这轮没有继续加。我原本就是想少折腾，已经多买了两台机器，暂时不想再多养几套服务。

## 先用一阵，再看稳定性

截至 10 月 27 日，三端的配置、香港直出、香港转美国、分流、DNS 和基本的服务器防护都做完了。Mac 继续用 HK-DMIT 工作，手机也已更新，不需要每次选节点再手动改一堆参数。

还没结束的是 DMIT 的直连问题，新的换 IP 工单还在等。这套中转能不能长期稳，得再用一阵才知道，测速说明不了。原来的机场继续留着备用。

接下来先正常用。没有具体问题的话，我不准备再往上加东西了。
